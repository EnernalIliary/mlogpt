# 01 · 模型结构

这一篇讲 `mlogpt-zh-0.72m` 到底是个什么东西：它的前向公式、每一张权重矩阵的形状、以及**为什么它必须长成这样**——因为目标平台（mlog）的约束比模型本身更硬。

> 本文写的是数学形式，用来解释「为什么能跑」。逐位核对请以 `mlogpt/reference.py` 的 `forward()` 为准：那一份才是和 mlog 蓝图内嵌 `ref` 对拍的实现，缩放常数、归一化的先后之类细节都以它为准。

| 项 | 值 |

| 参数量 | 721,152 |

| 类型 | decoder-only，字符级语言模型 |

参数量很小，小到可以把它当成一个「可以完整讲清楚的模型」：下面每一张矩阵都会给出形状和元素个数，加起来正好 721,152。

---

## 1. 记号

| 符号 | 含义 |
| --- | --- |
| `t` | token id，0..4095 |
| `X` | 嵌入矩阵，形状 `S × d` = `16 × 128` |
| `X[j]` | 第 j 个上下文位置的行向量（128 维） |
| `h` | 当前正在算的那一个位置的隐藏向量（128 维） |
| `Wq Wk Wv Wo` | 128 × 128 |
| `W1` | 512 × 128；`W2` 是 128 × 512 |
| `g, b` | LayerNorm 的 gain 与 bias，各 128 维 |
| `Wout` | 4096 × 128，输出头 |

整个前向里只有 `h`（一个 128 维向量）在往深处走；`X` 从头到尾不变。这是后面所有简化的根。

---

## 2. 嵌入：没有表，只有一条正弦

通常的语言模型第一层是一张 `V × d` 的嵌入表，查表得到 `X[t]`。这里没有表。`X[t]` 是**解析式算出来的**（随机傅里叶特征形式）：

```
a_i = 0.017 * (1 + i) ** 0.7
b_i = 2.399963229728653 * (i + 1)
X[t][i] = sin(a_i * t + b_i)          i = 0 .. d-1 = 0 .. 127
```

其中 `t` 是 token id（不是位置），`i` 是维度下标。

三个细节：

- `a_i` 随 `i` 缓慢增长（指数 0.7），所以低频维度负责区分「相邻 id」，高频维度负责区分「远处的 id」——和位置编码的频率梯度的思路同源，但这里的自变量是**词 id**，不是位置。
- `b_i` 的系数 2.399963229728653 就是黄金角（约 137.5°）的弧度值，乘 `(i+1)` 让相邻维度的相位尽量不重合，避免 128 维塌到少数几个值上。
- `t` 是整数，所以同一个 token 在任何上下文里的嵌入**完全相同**——它没有上下文相关的表示，就是一个固定的伪随机向量。

**为什么不用表？** 全尺寸阵列只有 170 个 memory cell。一张 `4096 × 128` 的 float32 表要 524,288 个数，塞不进去；就算塞得进去，每个 token 都要一次寻址读 128 个数，语句数也受不了。解析式嵌入把「读表」换成「算 128 次 sin」，而且 `a_i`、`b_i` 可以在生成蓝图时就折成常量，运行时只剩一条 sin 加一次乘加。

代价也很直接：**嵌入是随机的、不可学习的**。模型没法自己决定「这个字该有怎样的向量」，只能学着在固定的伪随机基底上做线性组合。这大概是它质量上最大的一个天花板。

---

## 3. 一个 block，跑四遍

参数表里只有**一套** `Wq/Wk/Wv/Wo/W1/W2/g/b`，没有 `Wq_1 … Wq_4`。所以「4 层」不是 4 套权重，而是同一组矩阵递归作用 4 次。

这不是猜测，是算出来的：一套 block（不含输出头）是 `4×128×128 + 512×128 + 128×512 + 2×128 = 196,864` 个参数。如果 4 层各有一套，总量会是 `4 × 196,864 + 524,288 ≈ 1.31M`，而不是 721,152。参数表能对上 721,152，只有「共享」这一种解释。

前向（pre-LN，残差）：

```
h = X[S-1]                                  # 只看最后那个位置

for li in 1..L:                             # L = 4，权重全程共享
    a = LayerNorm(h)                        # pre-LN：LN 在子层入口
    q = a @ Wq                              # 128

    K = X[0..S-2] @ Wk                      # (S-1) × 128
    V = X[0..S-2] @ Wv                      # (S-1) × 128
    s = q @ K.T / sqrt(d)                   # (S-1)，单头
    alpha = softmax(s)
    c = alpha @ V                           # 128

    h = h + c @ Wo                          # 残差

    m = LayerNorm(h)                        # 再一次 pre-LN
    h = h + relu(m @ W1) @ W2               # 512 → 128，残差

logits = h @ Wout                            # 4096
```

读这个伪代码要注意三件事：

1. **`h` 是 128 维的一个向量，不是一个序列。** `X[0..S-2]` 只在注意力里当 K/V 用，从不被更新。所以整张计算图是一条链，不是一棵树。
2. **`K` 和 `V` 在 4 层里是同一份。** `X` 不变、`Wk/Wv` 共享，所以 `K = X @ Wk`、`V = X @ Wv` 与 `li` 无关，只算一次就够。这是结构白送的一次常量折叠（见 [04-performance.md](04-performance.md) 的提速方向）。
3. **`sqrt(d)` 之类的缩放常数在生成侧被折进常量**，不额外占语句。

---

## 4. 只有最后一个位置跨层流动

这是整个设计里最关键、也最反直觉的一条。

标准 Transformer 每一层都维护一个 `S × d` 的隐藏状态，每个位置各自更新，位置之间靠注意力交换信息。这里不是：第 `li` 层把**输入嵌入** `X[0..S-2]` 直接当 context（不参与更新），只有第 `S-1` 个位置的 `h` 被更新。

结果就是：层与层之间传递的只有一个 128 维向量 `h`，而 context 侧永远是那 16 行嵌入。这等价于「线性／递归式」的前向：一个把固定上下文反复读 4 遍的循环体。

带来的语句数量级变化：

| 写法 | 每个 token 的语句数 |
| --- | --- |
| 标准（每层都维护 `S × d`） | O(S · L · d²) |
| 只最后一个位置流动 | O(L · d²) |

差一个 `S = 16` 的因子。全尺寸前向实测 7,362,930 条语句、铺了 10,786 台处理器、单台最多 983 行；如果按标准写法乘以 16，这个规模在游戏里没有落地可能。**这条简化不是审美选择，是能不能跑起来的分界线。**

它损失了什么？位置之间的交互只剩下「一层注意力」。模型没法在深层反复组合上下文——第 2、3、4 层看到的 context 和第 1 层一模一样，只是 `q` 变了。所以它擅长的是「给定一小段上文，猜下一个字」这种局部统计，做不了需要多步推理的事。这与它 18.5% 的 top-1 是自洽的。

## 5. 输出头与采样

输出层是一张 `4096 × 128` 的矩阵，把 `h` 投到 4096 个字符的 logits 上。它是全套权重里最大的一块：524,288 个参数，占 721,152 的 **72.7%**。也就是说这个模型四分之三的参数花在「把 128 维变成 4096 个分数」上，而不是花在理解上。

采样不走「softmax 之后按分布抽」的常规路线——那需要把 4096 个概率存下来再累加，语句数和内存都吃不消。这里用的是**一次比较采样**：

```
logits[0..V-1]
tot = sum(exp(logits[v] / T))        # T = 1.0，边算边累加
r   = 随机数 * tot                    # 一次随机数
扫一遍 v：累加 exp(logits[v]/T)，第一次超过 r 就取 v
```

等价于按 softmax 分布采样，但只需要一个累加器和一个阈值，O(V) 次加法和 O(1) 内存。生成用的随机数来自阵列里的固定种子序列，所以**同样的输入会得到同样的输出**——这也是能做逐位对拍的前提。

| 张量 | 形状 | 元素数 |

注意表里**没有** `pos_emb`、没有 `lm_head_bias`、没有 per-layer 前缀。少一样都凑不出 721,152，多一样也凑不出。

## 7. 为什么必须这么简化

把上面每一条简化摊开看，几乎都能追到同一个来源：mlog 是一个**没有数组、没有指针、没有动态内存**的汇编式语言，而目标平台还有硬额度。

### 7.1 单台处理器最多 999 条语句

这是 mlog 的硬上限。生成器按 `--cap 900` 切块，实测单台最多 983 行——已经在贴着天花板走。想加宽一层（比如 d 从 128 到 256），矩阵乘的语句数按 d² 涨 4 倍，块数也跟着涨 4 倍：10,786 台会变成四万多台，这在游戏里已经不是「蓝图」而是「工程事故」。

### 7.2 单台每 tick 最多 1000 条

`setrate 1000` 把处理器的执行速率顶到 1000 条/tick/台。这是**上限**，不是常态——真正限制吞吐的是下面的同步。

### 7.3 跨处理器只能靠 memory cell + barrier

没有共享内存、没有消息队列。两个处理器要交换一个数，必须「A 写 memory cell → barrier → B 读」。一次前向要跨 7~8 个同步点，这个数字比语句总数更能解释它为什么慢（见 [04](04-performance.md)）。

### 7.4 整个阵列只有 170 个 memory cell

这条约束同时杀死了两件事：嵌入表（`4096 × 128`）和「把权重放内存里」。所以权重必须在生成蓝图时**编进语句常量**——这也是 71.32 MB 产物的来源之一。

### 7.5 没有数组与间接寻址

一条 `op add a b c` 只能算标量。矩阵乘只能逐元素展开：读、乘、加、写。没有循环可以「省」语句，循环只能靠重复的直线代码表示（或用 jump 手写，但 jump 会把 1000 条/tick 的预算吃掉）。这就是为什么 721K 参数会膨胀成 8,756,803 条语句。

一句话总结：**这个模型的形状不是由「什么结构效果好」决定的，而是由「什么结构能在 999 条/台、170 个格子、7~8 个同步点的预算里活下来」决定的。**

## 8. 每条简化损失了什么

| 简化 | 省下了什么 | 代价 |
| --- | --- | --- |
| 解析式嵌入（无表） | 524,288 个数的存储 + 每 token 的查表语句 | 嵌入不可学习，表示是随机的 |
| 4 层共享一套权重 | 约 59 万参数、约 4 倍的层语句 | 深度有了但容量没跟着涨 |
| 只最后一个位置流动 | 一个 S = 16 的因子 | 层间无法反复组合上下文 |
| 单头注意力 | 4 份投影矩阵 → 1 份 | 只能学一种「关注方式」 |
| 无 bias | 每条投影少一次加法 | 表达力略降（影响很小） |
| 窗口 S = 16 | 注意力语句数线性下降 | 上下文只有 15 个 token |
| 字符级 4096 词表 | 词表小、输出头可控 | 序列长，16 个 token 只够几个词 |

## 9. 常见误解与反例

**误解：4 层就是 4 套权重，只是没在文件名里体现。**
反例：一套 block 是 196,864 个参数，4 套加上输出头约 1.31M。而文件里总共 721,152 个参数，连 4 套 block 都装不下。所以「4 层」只能是同一组矩阵递归 4 次——它更接近一个跑了 4 步的递归网络，而不是一个 4 层的堆叠网络。

**误解：`sin(a_i·t + b_i)` 是位置编码，模型另外还有词嵌入。**
反例：没有另外的词嵌入。`t` 是**词 id**，所以这条正弦**就是**词的表示，同时也是唯一的输入。它跟 Transformer 里那个加在词向量上的位置编码不是一回事：这里没有位置项，位置信息完全由「这个 token 在 `X` 的第几行」隐式给出。

**误解：既然只有最后一个位置流动，那前面 15 个位置白算了。**
反例：前面 15 行是注意力的 K/V 来源，是它唯一的上下文输入。省掉它们模型就退化成「只看当前 token」的 bigram。真正白算的是**重复**：4 层里 `K`、`V` 每次都被重算，而它们与层无关（见 §3 第 2 点）——这是浪费，不是冗余设计。

**误解：pre-LN 只是训练时的稳定技巧，推理时无所谓。**
反例：这里 pre-LN 是**结构的一部分**。`h` 要被同一个 block 递归 4 次，残差主干上的尺度会累积；LN 放在子层入口，才能保证每次进入 `Wq`/`W1` 的输入量级一致。另外 `g`、`b` 是全模型唯一一组「跨层共享的仿射参数」，去掉它们，4 次递归后的数值范围会漂。

**误解：窗口 16 就是「记得住 16 个字」。**
反例：生成是自回归的，新生成的字会滑进窗口尾部，所以 16 个 token 之后最早的输入会被挤出去。它记得住的是「最近 15 个 token」，不是你开头写的那句话。

## 10. 自己核对

想验证这篇文档里的公式对不对，不需要游戏，也不需要 jar：

```bash
# numpy 参考前向，直接打印采样出的 token id
python mlogpt/reference.py --weights weights/mlogpt-zh-0.72m-fp32.npz \
  --vocab weights/vocab-zh-4096.json --text 量持法 --N 8
```

实测输出：`[45,390,400,18,196,45,2,127]`，对应屏幕上显示的「同任意只相同（所」。

想连蓝图一起验，就先 `--build` 出 `.msch`（里面内嵌了同一份 `ref`），再用 `--run` 走真实执行器。两条路给出同一串 id，才说明「数学形式」和「mlog 指令流」是一回事。
